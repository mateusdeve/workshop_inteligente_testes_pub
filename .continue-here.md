<decisions_made>

- WebFetch do CLI local tem acesso ao Facebook API (IP residencial). RemoteTrigger nao tem (IP datacenter).
- A abordagem correta para Facebook Ads e sempre rodar local (CLI ou script), nunca cloud puro.
- CronCreate com durable:true nao funciona como documentado — nao persiste em disco.
- `enviar-relatorio-ads` usa WebFetch para Facebook GET e curl Bash para Z-API POST (WebFetch nao suporta POST).
- `ads-relatorio` mantida sem excluir, mas pausada. `enviar-relatorio-ads` e a nova direcao para uso simples.
</decisions_made>
